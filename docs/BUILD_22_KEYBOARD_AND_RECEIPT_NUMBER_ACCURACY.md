## 問題と原因

### 1. 別の場所をタップしてもキーボードが閉じない

- 支出の追加・編集の画面（レシートの確認画面も同じ画面）と、支出の詳細の明細を直す欄には、キーボードを閉じる仕組みがありませんでした
- iPhone の数字のキーボード（金額・単価）には「改行」も「完了」も無いため、一度開くと閉じる方法がありませんでした
- 入力欄ごとの「今どこに入力しているか」（`@FocusState`）も持っていなかったため、「完了」を作っても閉じる先がありませんでした

### 2. 数字（合計金額・商品の金額・数量・単価）がまだ不正確

Build 21 までの決め方を、架空の合成レシート42枚（下の「合成レシート」）で確かめたところ、次の原因が分かりました。

| 原因 | 例 | Build 21 の結果 |
| --- | --- | --- |
| 文字認識の数字の読み違い（O と 0、I・l と 1、S と 5、B と 8 など） | 「合計 ¥1,2OO」「¥l,98O」「S00円」「¥3,B2O」 | 空、または間違った金額（¥20 など） |
| 点の3桁区切り・区切りのあとの空白 | 「合計 1.234」「¥1, 234」 | 空、または ¥234 |
| 見出しと金額の間に短い行がある・数字が2行に分かれる | 「合計」「(税込)」「¥1,000」／「¥3,」「520」 | 空 |
| 「現計」を合計の見出しとして知らない | 「現計 ¥2,200」 | 空 |

| Vision の2番目・3番目の読み方を使っていない | 1番目「¥3,820」・2番目「¥3,520」 | **¥3,820 を自動で入れた** |
| 薄い印字のレシートを1回しか読まない | かすれた「合計 ¥786」 | ¥6 を自動で入れた |

| 閉じるとき | 仕組み |

使っている画面：

- 支出の追加・編集（手入力・レシートの確認画面。店名と金額の欄）
- レシートの確認画面の中の商品明細（商品名・数量・単価・金額の欄）
- 支出の詳細の、明細を直す欄（商品名・数量・単価・金額）

背景のタップの仕組み（`LifeOS/DesignSystem/Components/LifeKeyboardDismissal.swift`）：

- 画面全体を覆う強いジェスチャー（`onTapGesture` を画面全体に付けるなど）は使っていません。ボタンが押せなくなるおそれがあるためです
- 代わりに、画面のウインドウに UIKit のタップの仕組みを付けます。`cancelsTouchesInView = false`（タップを奪わない）・`delaysTouchesBegan／Ended = false`（遅らせない）・ほかのジェスチャーと同時に動く、にしてあるので、**候補・保存・キャンセル・ごみ箱のボタンは今までどおり1回のタップで動きます**（押すと同時にキーボードも閉じます）
- 入力欄（とその中）のタップでは閉じません。店名の欄から金額の欄へ、そのまま移れます
- 画面が閉じたら、付けた仕組みを外します
- 閉じるだけで、入力した文字は変えません

アクセシビリティ：「完了」には VoiceOver の説明（「キーボードを閉じます。入力した内容はそのまま残ります」）を付けました。背景のタップの見えない部品は VoiceOver に出しません。押す場所の大きさ（44pt 以上）は変えていません。
確認画面の商品明細の数量の欄は、小数（Build 21 から保存できる）が入るよう、小数点のある数字キーボードにしました（詳細画面と同じ。保存の決まりは変えていない）。

## 数字の決め方

すべて iPhone の中の計算です。読み取った文字・候補・位置・信頼度は、確認画面を開くまでに捨てます（下の「保存しない情報」）。

### 1. 数字の読み違いを直す（`ReceiptNumberText`）

- 直す文字：O・o → 0、I・l・| → 1、Z・z → 2、S・s → 5、G → 6、B → 8
- **金額のはずの場所だけ** を直します：「¥」「￥」のあと、「円」の前、行の右端（※・★・軽・外・内・非 などの印のあとも行の右端とみなす）
- 行の右端は、数字が2つ以上・英字が1つまでのときだけ直します（商品名の「S2」「BOSS」などは直さない）。「¥」のあと・「円」の前は、英字が数字より多くなければ直します
- 「1.234」「12.345.678」（点の3桁区切り）は「1,234」にします（「1.5」のような小数はそのまま）
- 「1, 234」「¥1 234」（区切りのあとの空白）は「1,234」にします
- 全角の数字・記号は、今までどおり半角にしてから読みます

### 2. 合計の見出しと金額を探す

- 見出し：今までの「合計」「総合計」「お買上金額」「お支払額」「ご請求額」「TOTAL」などに、**「現計」** を足しました
- 見出しの行の右側（同じ行）の金額 → 無ければ直下の金額だけの行
- **Build 22**：見出しと金額の間に、短い行（8文字まで・数字なし・見出しでない。「(税込)」など）が1つあっても読みます。「¥3,」と「520」のように2行に分かれた数字もつなぎます
- 合計にしない数字（今までどおり）：お預り・お釣り・ポイント・カード番号・電話番号・郵便番号・時刻・伝票番号・レジ番号・点数・税・値引き・小計（小計は「選択非推奨」の参考の候補だけ）

### 3. 計算で確かめる（`ReceiptTotalsEvidence`）

レシートの中のほかの数字から、合計になるはずの金額を3つの別々の方法で計算します。

| 方法 | 計算 |
| --- | --- |
| 小計から | 小計＋外税、小計＋外税－値引き（値引きが小計に含まれている形・含まれていない形の両方） |
| 支払いから | お預り－お釣り（ポイントで払った分を足した形も） |
| 商品明細から | 明細の金額の合計（＋外税、－値引きの形も。すべての明細に金額があるときだけ） |

- 外税・消費税は 8% と 10% の行を足します。**内税（「内消費税」「(8%対象 … 内税 …)」）は足しません**
- 値引きは「-30」「▲50」「△20」「−100」「▲1,000」のどれでも読みます。「10%引」の割引率・「3点」の点数は金額にしません
- 計算と合う候補は、順位を上げます（見出しの強さの方が優先）
- 数量×単価＝金額 も、商品明細の1行ごとに確かめます

### 4. Vision のほかの読み方を使う

- 文字のまとまりごとに、Vision の上位3つの読み方を受け取ります（1番目が今までどおりの文字）
- 2番目・3番目は、**計算と合うときだけ** 使います。1番目の読み方が計算と合っていれば変えません。確かめる手掛かりが無ければ1番目のままです
- 商品明細は、数量×単価が金額と合わない・金額が読めないときだけ、ほかの読み方で合うものを使います
- ほかの読み方で作る行は、1行につき3つまでです

### 5. 薄い印字のレシート

- 1回目の読み取りの精度が低いとき（文字が15文字未満、または平均の信頼度が 0.5 未満）だけ、写真を白黒にし、コントラストを上げ（1.4倍）、薄い文字を濃くして（ガンマ 1.5）、もう1回だけ読みます
- 2回の結果のうち、良い方（文字の数×平均の信頼度）を使います。同じなら1回目です

## 自動で金額を入れない条件

次のときは金額欄を空にして、理由を出します（推測した金額は入れません）。候補は出すので、レシートを見て選ぶか入力できます。

| 条件 | 確認画面の一言 |
| --- | --- |
| 合計の見出しの近くに金額が無い | 合計金額を読み取れませんでした。… |
| 強い候補（同じ強さの見出し）が別々の金額 | 合計金額の候補が複数あるため、金額を空にしました。… |
| **Build 22**：読んだ合計が、2つ以上の別々の計算がそろって示す金額と違う | 合計金額が、小計・税やお預り・お釣りから計算した金額と合わないため、空にしました。… |

- 計算でそろった金額が候補に無いときは、「¥X（小計・税などから計算・確認してください）」の候補として出します。**この候補は自動では選びません**（利用者が選んだときだけ金額欄に入ります）
- 読んだ合計と合わない計算が1つだけのときは、金額を入れたうえで「合計金額が、小計・税やお預り・お釣りから計算した金額と合いません。レシートで確かめてください。」と出します
- 商品明細の数量×単価が金額と合わないときは、その明細に「数量×単価と金額が合いません。レシートで確かめてください。」と出します（値は変えません）
- 小計は今までどおり自動では選びません

## 実機確認手順（Build 22）

キーボード：

1. お金 →「レシートを読み取る」→ 確認画面で店名の欄をタップ → 何も無い場所をタップ → キーボードが閉じる（店名はそのまま）
2. 金額の欄をタップ → キーボードの上の「完了」→ 閉じる（金額はそのまま）
3. 金額の欄に入力中に、画面を上下にスクロール → 閉じる
4. 入力中に、合計金額の候補・店名の候補をタップ → 1回のタップで選べて、キーボードも閉じる
5. 入力中に「保存」「キャンセル」→ 1回のタップで動く
6. 店名の欄から金額の欄をタップ → キーボードは閉じずに金額の欄へ移る
7. 確認画面の商品明細の欄（商品名・数量・単価・金額）でも 1〜3
8. 支出の詳細 → 明細をタップして直す欄 → 1〜3、「保存」「やめる」が1回で動く
9. VoiceOver をオンにして「完了」が読み上げられる

数字（レシートの枚数・種類ごとに、合計金額が正しく入ったか・空になったか・間違った金額が入ったかを教えてください）：

1. コンビニ・スーパー・ドラッグストア・飲食店・ガソリンスタンドのレシート
2. 8% と 10% が混ざったレシート・値引きやクーポンのあるレシート・ポイントで払ったレシート
3. 印字が薄い・かすれたレシート、長いレシート
4. 合計が空になったときに、理由の一言と候補が出る（計算した候補は「確認してください」と出て、自動では入らない）
5. 商品明細の数量・単価・金額（合わないときは「数量×単価と金額が合いません」）
6. 読み取りにかかる時間が Build 21 と比べて長すぎないか（薄いレシートだけ少し長くなることがある）

今までの機能：Build 21 の明細の保存・詳細・修正・削除、保証書の読み取り、予定・ToDo・買い物、通知、招待、自分だけ／共有の切り替え。

## リスク

- **読み違いを直す決まりの誤り**：金額の場所だけを直すようにしたが、「¥」のあとの英字の型番などがあれば数字に直してしまうおそれがある。計算で確かめる仕組みがあるので、合わなければ自動では入れない
- **2回目の読み取りの時間**：精度が低いときだけ1回増える（上限2回）。実機で時間を確かめる
- **計算で確かめる仕組みの限界**：小計・税・お預り・お釣りが無いレシートでは確かめられない（今までどおりの決め方）。そのときは Vision のほかの読み方も使わない
- **キーボードの閉じ方**：ウインドウにタップの仕組みを付けるのは、UIKit の標準の方法だが、Xcode・実機でまだ動かしていない（シートの上での動きを実機で確かめる）
- **Python の道具**：Swift の決め方を写したもので、細かい違いがあり得る。本当の結果は Xcode のテストで確かめる
- **RecognizeDocumentsRequest**：使っていないため、その精度の向上は入っていない
