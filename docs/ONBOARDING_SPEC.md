2026-10-09 に受け取った指示をそのまま保存しています（実装の正）。実装の解釈は [IMPLEMENTATION_NOTES.md](IMPLEMENTATION_NOTES.md) の「はじめての設定」、報告は [AFTER_CALM_FUTURE.md](AFTER_CALM_FUTURE.md) の「4. はじめての設定」。

## 目的

生活OSの次の開発段階として、初回起動時の「はじめての設定」を実装してください。

目的は、初めて使う人が説明なしで自分の生活情報を設定し、60秒以内に「今日」画面で生活OSの価値を体験できるようにすることです。

単にオンボーディング画面を追加するのではなく、現在のMockデータ中心の初期状態を、利用者自身の生活から始まる状態へ変更してください。

## 現在の状態

リポジトリ：

`tomoking945-boop/life-os`

ブランチ：

`main`

現在は以下まで実装・確認済みです。

- Calm Futureの全4段階
- 入力時刻の読み取り
- 柔らかい時間の選択
- Inbox修正内容の保存
- テーマとダークモード
- 習慣の追加・編集・削除
- Xcodeビルド成功
- 既存テスト138件成功
- Simulator確認でエラーなし

アプリはSwiftUIで実装されています。

現在の初回起動では、`LifeStore.persistent()`が保存データのない場合にMockデータを使用します。今後は、新規利用者の本番利用では見本データを入れず、初回設定から本人のデータを作る形に変更します。

プレビューや開発確認では、引き続きMockデータを利用できるようにしてください。

## 実装するもの

初回起動時に表示する「はじめての設定」フローを実装してください。

### 画面構成

全体を4ステップ程度にまとめ、60秒以内で完了できる構成にしてください。

#### 1. ようこそ

表示内容：

- 見出し：`生活OSへようこそ`
- 説明：`予定や家事、やることをひとつにまとめて、「今日やること」を見やすくします。`
- 主ボタン：`はじめる`

この画面では、細かい機能説明やPremiumの案内を表示しないでください。

#### 2. 使い方の選択

質問：

`どのように使いますか？`

選択肢：

- `ひとりで使う`
- `家族・パートナーと使う`

説明：

- ひとりで使う：`自分の予定や習慣をまとめます`
- 家族・パートナーと使う：`自分と共有の情報を分けて管理します`

選択結果を既存の`UsageStyle`へ反映してください。

共有機能はまだ外部同期されていないため、「相手とすぐ同期される」と誤認させる表現は使用しないでください。

#### 3. 名前の設定

入力項目：

- `あなたの名前`
- 家族・パートナーモードの場合のみ`生活グループ名`

生活グループ名の例：

`池上家`

名前は空白だけでは次へ進めないようにしてください。

入力した名前は、既存の`UserProfile`と現在利用者のメンバー名へ反映してください。

#### 4. 最初の習慣を選ぶ

質問：

`今日から始めることはありますか？`

複数選択できる候補：

- `水を飲む`
- `薬を飲む`
- `ストレッチ`
- `散歩する`
- `日記を書く`

すべて選ばなくても完了できるようにしてください。

候補の扱い：

- 水を飲む：毎日・軽い習慣
- 薬を飲む：毎日
- ストレッチ：毎日・軽い習慣
- 散歩する：毎日・軽い習慣
- 日記を書く：毎日

既存の`Habit`と`LifeStore.addHabit`を使用し、選んだ習慣を今日から開始してください。

すでに同じ名前の習慣がある場合は重複登録しないでください。

完了ボタン：

`生活OSをはじめる`

完了後は「今日」画面へ移動してください。

初期データが何も選ばれなかった場合も正常に完了し、空の「今日」画面を表示してください。

## 初回起動の判定

`AppState`に初回設定の完了状態を追加してください。

推奨する状態：

```swift
var hasCompletedOnboarding: Bool
```

保存用の`Settings`では、以前の保存データとの互換性のためOptionalとして追加してください。

```swift
var hasCompletedOnboarding: Bool?
```

読み込み時の扱い：

- 新規インストール：`false`
- 以前のバージョンからの利用者：`true`
- 初回設定完了後：`true`

以前から保存データがある利用者に、アップデート後突然オンボーディングを表示しないでください。

初回設定の途中でアプリを終了しても、再起動後に続きから再開できるようにしてください。

必要であれば、以下のようなCodableの進行状態を追加してください。

```swift
struct OnboardingProgress: Codable, Hashable {
    var step: Int
    var usageStyle: UsageStyle?
    var name: String
    var groupName: String
    var selectedStarterIDs: Set<String>
}
```

進行状態と入力内容は端末内だけに保存し、外部へ送信しないでください。

初回設定完了後は進行状態を削除してください。

## 初期データの変更

現在の`LifeStore.persistent()`は、保存データがない場合にMockデータで始まります。

次のように役割を分けてください。

- 新規利用者の実行環境：空のデータから開始
- SwiftUI Preview：これまでどおりMockデータ
- テスト：必要なデータを明示して生成
- 既存利用者：保存済みデータをそのまま読み込む

実装方法は既存構造を確認した上で決めて構いませんが、次のようなAPIを検討してください。

```swift
static func persistent(startEmptyIfNoSavedData: Bool) -> LifeStore
```

または、目的が明確になる別の命名でも構いません。

`LifeOSApp`では、先に`AppState`を読み込み、その初回設定状態をもとに`LifeStore`の初期状態を決定してください。

新規利用者用の空データを作る際は、各モデルの既存イニシャライザを確認し、無理にMockデータを混ぜないでください。

## 画面遷移

アプリの最上位で、次のように表示を切り替えてください。

```text
初回設定未完了
    ↓
OnboardingView

初回設定完了
    ↓
MainTabView
```

初回設定完了時は、今日タブを選択した状態にしてください。

画面遷移は戻れない一方通行にせず、設定途中では前のステップへ戻れるようにしてください。

完了処理の二重実行によって、習慣が重複登録されないようにしてください。

## 初回設定の完了処理

完了ボタンを押したときは、次の順序を基本にしてください。

1. 入力内容を検証
2. 利用スタイルを保存
3. 名前と生活グループ名を保存
4. 選択された習慣を重複なく追加
5. 初回設定完了を保存
6. 一時的な進行状態を削除
7. 今日タブを選択
8. `MainTabView`へ遷移

途中で処理が複数回呼ばれても、同じ習慣が重複しないようにしてください。

## 開発用設定

既存の開発用設定画面に、可能であれば以下を追加してください。

`はじめての設定を再表示`

この操作では、現在の予定・習慣・メモなどを削除しないでください。

再表示後に同じスターター習慣を選んでも、重複登録しないようにしてください。

データをすべて削除する操作は、今回追加しないでください。

## 既存機能を壊すリスク

特に次を注意して確認してください。

- 既存利用者に初回設定が再表示される
- 新規利用者にMockデータが混ざる
- PreviewからMockデータが消える
- 初回設定完了前に`MainTabView`が一瞬表示される
- 完了ボタンの連打で習慣が重複する
- 初回設定の途中終了で入力内容が失われる
- 一人モードなのに共有フィルターが表示される
- 既存の保存ファイルがデコードできなくなる
- テーマ変更時に初回設定が最初へ戻る
- ダークモードで文字や選択状態が見えなくなる

以前の保存形式との後方互換を維持してください。

## 自動テスト

`LifeOSTests/OnboardingTests.swift`を追加し、少なくとも以下をテストしてください。

1. 新規利用者は初回設定未完了になる
2. 以前の設定データに完了状態がない場合は完了済みとして扱う
3. 一人モードの選択が保存される
4. 家族・パートナーモードの選択が保存される
5. 空白だけの名前では完了できない
6. 名前の前後の空白が取り除かれる
7. 現在利用者のメンバー名も更新される
8. 生活グループ名が保存される
9. 選択した習慣だけが追加される
10. 軽い習慣の設定が正しい
11. 同じ習慣を再度選んでも重複しない
12. 何も選ばなくても完了できる
13. 初回設定完了後に進行状態が削除される
14. 途中のステップと入力内容を復元できる

16. Preview用のMockデータ生成が維持される
17. 既存の138件のテストがすべて成功する

ストレージを使うテストは、実際の利用者データと衝突しない一時保存先を使用してください。

## Simulator確認

次の操作を確認してください。

### 新規利用者

1. 保存データのない状態で起動
2. MainTabViewではなく「生活OSへようこそ」が表示される
3. 一人モードを選ぶ
4. 名前を入力
5. 水を飲む・ストレッチを選択
6. 初回設定を完了
7. 今日画面に選んだ習慣だけが表示される
8. Mockの予定・支出・メモが表示されない
9. アプリを終了して再起動
10. 初回設定は表示されず、今日画面から始まる

### 共有モード

1. 家族・パートナーと使うを選択
2. 名前と生活グループ名を入力
3. 完了後、すべて／自分／共有の切り替えが表示される
4. 実際の同期が行われると誤解する表示がない

### 途中終了

1. 名前入力まで進む
2. アプリを終了
3. 再起動
4. 続きから再開され、入力内容が残っている

### 既存利用者

1.現在のバージョンで保存データを作る
2. 更新版を起動する
3. 初回設定が表示されない
4. 既存の予定・習慣・Inbox・設定が残っている

### アクセシビリティ

## 完了条件

以下をすべて満たした場合のみ完了としてください。

- 新規利用者に初回設定が表示される

- 初回設定が60秒程度で完了できる
- 本番の新規利用者にMockデータが入らない
- 選んだ習慣が今日画面へ表示される
- 何も選ばなくても正常に開始できる
- 途中終了後に続きから再開できる
- 習慣が重複登録されない
- 入力内容が端末内だけに保存される
- 既存データとの互換性が保たれる
- ライト／ダークとテーマが正しく反映される
- Dynamic TypeとVoiceOverで操作できる
- 既存138件を含む全テストが成功する
- Xcodeビルドが成功する
- Simulator確認が完了する
- ドキュメントが実際の確認結果と一致する
