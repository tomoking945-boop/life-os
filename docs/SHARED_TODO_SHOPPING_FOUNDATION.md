## 調べたこと（書き始める前の確認）

- ToDo・買い物は、どちらも `LifeItem`（種類 `todo`・`shopping`）。端末の中の `life-store.json` に保存（`LifeStore`）
- 「持ち主」（`Ownership`：自分／共有）は以前からあったが、**端末の中で印を付けるだけ**で、どこにも送っていなかった
  - 「パートナーと共有」ボタン（今日・カレンダー）、なんでも追加の「自分 / 共有」、整理の「自分 / 共有」、自動の分類（「妻と」などで共有にする）が、この印を付けていた
- 古い「生活グループ」画面（`GroupSettingsView`）・「共有メンバー」（`MembersView`）・Mock の招待（`SharingFlowView`・`WelcomeView`・`SharedStarterView`）は、端末の中だけの画面だった
- Firebase の「わが家」（`HouseholdService`・Cloud Functions）は、作成・招待・参加まで。Firestore の共有項目（`groups/{groupID}/items`）の場所と Security Rules・索引・通知（`onSharedItemWritten`）は公開済みだが、アプリはまだ使っていなかった
- 以前の下準備（`SharedItemRecord`・`SharedSyncPolicy`・`SharedMigrationPlan`）は、アプリの中で UID を扱う形・4種類（予定・ToDo・家事・買い物）・既存データの一括移行の形だった

### 採用した方針（二重のモデルにしないために）

- 項目のモデルは、これまでの `LifeItem` をそのまま使う（新しい項目の型は作らない）
- 共有項目は、`LifeStore` の中の **`householdItems`**（Firestore から受け取る一覧。端末の `life-store.json` には保存しない）に置き、画面では端末の項目と一緒に出す（`visibleItems`）
- Firestore に書く形は `SharedItemPayload`（`LifeOS/Core/Sharing/HouseholdItems.swift`）で決める。以前の `SharedItemRecord` は、アプリの中で UID を扱う形なので使わない（UID は Firebase の窓口だけが付ける）。`SharedItemRecord`・`SharedSyncPolicy`・`SharedMigrationPlan` は、以前のテストのために残し、アプリの同期には使わない（コメントで明記。`SharedMigrationPlan` を使っていないことはテストで確かめる）
- 保存先は既存の `groups/{groupID}/items/{itemID}`（新しいコレクションは作らない）。索引の変更は不要

## 第1段階：わが家の管理と画面の整理

### 古い「生活グループ」の扱い

- プロフィールの「生活グループ」「共有メンバー」の行と、その画面を **削除**。入口は「共有用アカウント・わが家」の1か所だけ
- Mock の招待画面（偽のリンク・コピー）、「二人の生活OSを30秒で作る」、今日・カレンダーの「パートナーと共有」ボタン（端末の中で印を付けるだけのもの）も削除
- 今日の「パートナーを招待」のカードは、**Firebase のわが家が自分1人のとき**だけ出し、押すとプロフィールと同じ「共有用アカウント・わが家」を開く（端末の中の Mock の「参加済み」は使わない）
- はじめての設定で「生活グループ名」を聞くのをやめた（端末の中のグループと Firebase のわが家が別々にできて迷うため）
- 端末の中に保存されている古いグループ名・メンバーの値は **消さず、Firebase へも送らない**（保存の形を変えないため値は残すが、画面では使わない）。自動の移行はしない
- 開発用設定の「パートナー参加済み」の切り替えを削除

### わが家の設定（共有用アカウント → わが家 → わが家の設定）

| 表示・操作 | 内容 |
| --- | --- |
| わが家の名前 | オーナー・パートナーのどちらでも変えられる（50文字まで・改行なし） |
| メンバー | あなた（オーナー／パートナー）・パートナー（参加中／参加待ち）。UID は出さない |
| 共有する種類 | ToDo・買い物のオン／オフ。ほかの種類（予定・家事・家計簿・保証書・リスト・メモ）は「今後対応」と表示するだけ |
| 招待の状態 | 有効な招待の期限・2人そろっている など（招待の作成・取り消しは前の画面） |
| 危険な操作 | わが家の削除（オーナーで1人のとき）・わが家から退出（パートナー） |

- 名前・種類の変更は Cloud Function `updateHousehold`（App Check 必須・サインイン必須）。サーバーが「いまメンバーか」をトランザクションの中で確かめる
- 種類：アプリが送るのは「ToDo・買い物のうち、オンにするもの」だけ。**保存されている「今後対応」の種類はサーバーがそのまま残す**（勝手に消さない）。変えたあと1つも残らない変更は断る
- オンにすると、その種類を作るときに「わが家で共有」を選べる。オフにすると新しい共有項目は作れない（Security Rules でも断る）が、**すでにある共有項目は消さない**（完了・編集・削除はこれまでどおりできる）
- 相手の端末への反映：アプリを開き直したとき・前面に戻ったとき・わが家の画面を開いたときに読み直す（リアルタイムではない。オフにした種類で作ろうとしても、サーバーが断り、項目は「自分だけ」として端末に残る）

### わが家を削除（`deleteHousehold`）

- オーナーだけ・メンバーが自分1人のときだけ。2人いるときは断る（`household-not-empty`）。パートナーは断る（`not-owner`）
- 画面で2回確認する（「わが家を削除しますか？」→「本当に削除しますか？」）
- サーバー：トランザクションでオーナー・1人を確かめ、未使用の招待を取り消してから、わが家の文書とその下（共有項目・メンバー・通知の記録）、招待、memberships を消す。途中で止まっても、もう一度呼べば続きから消す
- サインインのアカウント（Firebase Authentication）と、端末の中の個人データは消さない。削除のあと、新しくわが家を作ることも、別の招待に参加することもできる

### わが家から退出（`leaveHousehold`）

- パートナーだけ。オーナーは退出できない（`owner-cannot-leave`）。**所有権の移し替えは次の段階**
- サーバー：トランザクションで自分のメンバー文書と memberships を消す。わが家・オーナー・共有項目は残す。自分が担当の共有項目は担当を null にする
- 退出したあとは、そのわが家の共有項目を読めない・書けない。別の招待に参加できる
- アプリからメンバー文書を直接消すことは、Security Rules で禁止した（以前は本人なら消せた。オーナーの退出の禁止・memberships の片付けをサーバーで必ず行うため）

## 第2段階：共有 ToDo・買い物

### 何を共有するか・何を送らないか

| 共有する（Firestore に送る） | 送らない（端末の中だけ） |
| --- | --- |
| 利用者が「わが家で共有」を選んだ ToDo・買い物だけ | 予定・家事・支払予定・習慣・お金・保証書・リスト・メモ・暮らしメモリー |
| | 既存の ToDo・買い物（以前の端末の中の「共有」の印が付いたものも）。一括アップロードはしない |
| | 「自分だけ」の項目すべて |

送る項目（1件あたり）：

| 項目 | 内容 |
| --- | --- |
| `schemaVersion` | 1（あとから変えられない） |
| `kind` | `todo` / `shopping`（あとから変えられない） |
| `title` | 名前（前後の空白を除き、200文字まで） |
| `date`・`hasTime` | 日付（今日の画面に出す日）・時刻があるか |
| `isCompleted` | 完了したか |
| `deferredTo`・`droppedAt` | 「あとで」で回した先・「もうやらない」にした日時（あれば） |
| `assigneeUID` | いまは常に null（担当の共有は次の段階） |
| `createdBy`・`updatedBy` | 作った人・最後に変えた人の UID（Firebase の窓口が入れる。画面・ログには出さない） |
| `createdAt`・`updatedAt` | サーバーの時刻 |

送らないもの：柔らかい時間（帰宅時など）、暮らしメモリーとのつながり、担当（自分／パートナー）、端末の中の持ち主の印、メール、Apple の情報。
買い物の数量・メモは、端末のモデルと画面で使っていないため、項目を作っていません。

### 個人／共有の決め方

- 新しく作るとき・編集するときに、保存先「自分だけ／わが家で共有」を選ぶ。**初期値は必ず「自分だけ」**
  - なんでも追加（種類を決めて追加・提案どおり追加・詳しく整える）、買い物（よく買うもの・献立から）、ToDo・買い物の編集
  - 「わが家で共有」は、わが家に参加していて、その種類がオンのときだけ出す
- **AI・自動の分類は「共有」を選ばない**。「妻と」「家族で」などの言葉があっても自分の項目にする（以前は自動で「共有」にしていた）。Inbox の整理からも共有にしない（整理の「自分 / 共有」は削除）
- 予定などを「わが家で共有」で追加しようとしても、その項目は「自分だけ」に保存する

### 画面

- 「すべて / 自分 / 共有」：今日・カレンダー（これまでどおり）、やること・買い物（今回追加。2026-09-28 の「やること画面には付けない」を変更）
  - 自分：端末の自分の項目。共有：わが家の共有項目（と、以前の端末の中の「共有」の印の項目）
- 共有項目には小さな共有マーク（2人の人の形）。読み上げでは「わが家で共有」
- 今日の画面では、自分の項目と共有項目を一緒に出す
- ToDo・買い物の行を長押し →「編集」：名前の変更・「わが家で共有」への変更・削除

### 同期・競合・オフライン

- Firestore のリアルタイム更新（`addSnapshotListener`）で、2台に反映する。追加・編集（名前）・完了・未完了に戻す・あとで・もうやらない・削除
- 文書の ID は端末の項目の UUID。**同じ操作をくり返しても1件のまま**（同じ ID の作成は Security Rules が断る。作成日時を変える上書きになるため）
- 自分の変更は、Firestore の一覧を受け取るたびに入れ替えるので、**二重に出ない**
- 競合：項目ごと・欄ごとに「あとから届いた変更」が残る（Firestore の通常の動き）。更新日時はサーバーの時刻で、端末の時刻では決めない
- オフライン：Firestore が端末にためておき、つながったら送る（標準の設定のまま）。そのあいだも画面には出る
- 通信できない・断られたとき：
  - 新しく作った共有項目が断られた（種類がオフにされていた など）→ **「自分だけ」として端末に残す**（消さない）。一言でお知らせ
  - 共有項目を読めなくなった（退出・わが家の削除）→ 共有項目の表示だけを消す。端末の個人データは消さない
- 自分だけ → わが家で共有：同じ ID で Firestore に作り、**サーバーで保存が確かめられてから**端末の項目を片付ける。それまでは共有の方だけを出す（二重に出さない）。断られたら端末の項目がそのまま残る。アプリを途中で閉じても、次に開いたとき、サーバーで確かめられた共有項目と同じ ID の端末の項目を片付ける
- わが家で共有 → 自分だけ：**今回は入れていません（次の段階）**。理由：相手の画面からも消すことになり、オフラインのあいだに相手が変えた内容との食い違い・二重・取りこぼしを避ける手順（端末に保存 → サーバーで削除の確認 → 失敗したら戻す）を、2台で確かめてから入れるため

### 権限（Security Rules と Functions）

| 決まり | Rules | Functions |
| --- | --- | --- |

| 更新者は操作した本人、更新日時・作成日時はサーバーの時刻 | ○ | — |
| 担当はメンバーか null | ○ | ○（退出時に null にする） |

| 招待トークン・UID・メールをログに出さない | — | ○（理由の短い言葉だけを返す・記録する） |

## 通知（`onSharedItemWritten`）の監査

| 確かめたこと | 結果 |
| --- | --- |
| 自分の操作を自分へ通知しない | 宛先の選別で、操作した本人のすべての端末を除く（`selectRecipients`） |
| 必要な通知だけ | ToDo・買い物は「追加」だけ。完了・名前の変更・削除は送らない |
| 1回の更新で重複しない | 同じ項目は30秒以内に1回だけ（`notificationLog` のトランザクション）・同じトークンは1回・`apns-collapse-id` |
| 個人項目では通知しない | 個人項目は Firestore に無いので、通知の処理が動かない。決まっていない種類・更新者の無い文書も送らない |
| 秘密情報を含めない | 内容の表示を許可していない端末には「共有情報が更新されました」だけ。UID・メール・トークンは本文に入れない（データには文書の ID だけ） |
| 準備の状況 | **アプリはまだ端末（FCM トークン）を登録していない**ため、宛先が0件になり、実際の通知は送られない。Function は公開済みのまま変えない（変える必要がないため公開もしない）。通知の記録（`notificationLog`）は項目ごとに1つでき、わが家の削除で一緒に消える |

1. 古い画面で迷わない：プロフィールに「生活グループ」「共有メンバー」が無く、「共有用アカウント・わが家」だけ。今日の招待のカードは、わが家が1人のときだけ出て、同じ画面を開く
2. わが家の設定：A が名前を変える → B がアプリを開き直すと新しい名前。B が買い物をオフ → A がアプリを開き直すと、買い物で「わが家で共有」が出ない。オンに戻す
3. 追加：A がなんでも追加で「わが家で共有」を選んで ToDo を追加 → B の今日・やることに共有マーク付きで出る。B が買い物で「わが家で共有」を選んで「牛乳」→ A の買い物に出る
4. 完了・編集・削除：B が完了 → A でも完了。A が未完了に戻す → B でも未完了。A が長押し →「編集」で名前を変える → B に反映。B が削除 → A からも消える
5. 自分だけの項目：A が「自分だけ」（初期値）で追加した ToDo・買い物、予定は B に出ない。「妻と旅行相談」と入れても「自分だけ」になる
6. 自分だけ → わが家で共有：A の既存の ToDo を長押し →「編集」→「わが家で共有」→ B に出る。A に二重に出ない
7. オフラインからの復帰：A を機内モードにして共有の ToDo を追加・完了 → A には出る・B には出ない → 機内モードを切る → B に出る（1件だけ）
8. 退出：B が「わが家の設定」→「わが家から退出」→ B から共有項目が消える。B の自分だけの項目は残る。A には共有項目が残る
9. 退出のあと：B は A のわが家を読めない。A が新しい招待を作り、B が参加し直せる
10. 削除：B が退出したあと、A が「わが家を削除」（2回確認）→ A の共有項目が消え、自分だけの項目は残る。A は別の招待に参加できる（B がわが家を作って A を招待）
11. 2人いるあいだ、A に「わが家を削除」が出ない・B に「削除」が出ない・A に「退出」が出ない

## 公開の順番（池上さんの許可のあとで行う）

この作業では何も公開していません。行うときは次の順番で、必ず `--only` を付けます（`firebase deploy` だけは使わない）。

1. Mac で全部のテストが通ることを確かめる
2. `firebase deploy --only functions`（`updateHousehold`・`deleteHousehold`・`leaveHousehold` が増え、`getMyHousehold` などが groupID を返す。既存の Build 6 はそのまま使える）
3. `firebase deploy --only firestore:rules`（Build 7 が送る `schemaVersion` を受け付け、ToDo・買い物だけを作れるようにする。**これより前に Build 7 で共有すると、サーバーが断り、項目は「自分だけ」に残る**）
4. 索引（`firestore.indexes.json`）・Hosting は変更なし（公開しない）
5. Build 7 を Archive して TestFlight へ

## 元に戻す方法

- このブランチは main に入れていない。やめるときはブランチを使わなければよい
- main に入れたあとで戻すときは、取り込みの commit を `git revert` する
- 公開したあとで戻すとき：
  - ルール：main の前の `firestore.rules` を `--only firestore:rules` で公開し直す（共有項目は Firestore に残る。古いアプリは共有項目を読まない）
  - Functions：前の `index.js` で `--only functions` を公開し直す（増えた3つは `firebase functions:delete` で消す）
  - アプリ：TestFlight で Build 6 を配る
- Firestore に残った共有項目は、わが家の削除（1人のとき）で消える

## 残る制約・次の段階

- わが家で共有 → 自分だけ：次の段階（理由は上）
- オーナーの引き継ぎ（所有権の移し替え）：次の段階。オーナーは2人いるあいだ退出・削除できない
- 担当（自分／パートナー）の共有：次の段階（いまは `assigneeUID` を常に null）
- 予定・家事・家計簿・保証書・リスト・メモの共有：今後対応
- プッシュ通知：アプリが端末を登録していないため、まだ届かない
- 共有する種類の変更は、相手の端末ではアプリを開き直したとき・前面に戻ったときに反映（リアルタイムではない）
- 共有項目には、端末の通知（リマインダー）を付けない
- 共有項目は Firestore の端末の一時保存（オフライン用）に置かれ、`life-store.json` には入らない。退出・削除のあとは端末に残らない
