# Build 15：カレンダーの予定を編集する・ToDoの日付を指定する

2026-11-01。ブランチ `build15-event-edit-and-todo-date`（最新の main `1ab4093` から）。

## 1. 何を作るか

カレンダーにある既存の予定を、追加し直さずに変更できるようにする。

- 予定の右側に鉛筆ボタン
- 変更できる項目：タイトル、日付、終日／時刻、時刻
- 自分だけの予定と、わが家で共有している予定の両方
- キャンセルでは何も変えない
- 保存後は変更した日を選び、その月を表示する
- 保存先（自分だけ／わが家で共有）は変更しない

加えて、ToDoに日付を指定できるようにする。

- 「なんでも追加 → 詳しく整える」で、予定だけでなくToDoにも日付欄を表示
- やること画面でToDoを長押し →「編集」から日付を変更
- 翌月・翌年など、先の日付まで上限なく選択
- 自分だけ・共有のToDoの両方に対応

## 2. なぜ必要か

Build 14 では追加・共有・削除まではできるが、時間や日付を間違えた場合に、一度削除して作り直す必要がある。作り直すと操作が増え、共有相手にも別の予定として見えるため、同じ予定をそのまま直せるようにする。

ToDoはこれまで追加時の日付（多くは今日）のままで、具体的な期限日へ移す入口が分かりにくかった。「今後」へ正しく並べ、指定した日に「今日」へ出せるようにする。

## 3. 画面と操作

1. カレンダーで日付を選ぶ
2. 予定の右側にある鉛筆を押す
3. 「予定を編集」でタイトル・日付・終日／時刻を変更
4. 「保存」で反映、「キャンセル」では変更しない

アクセシビリティ：

- 鉛筆ボタンは44×44ポイント以上
- 読み上げは「予定を編集」
- UIテスト用の識別子は `calendar.editEvent`
- 保存ボタンは `calendar.saveEvent`

編集画面では保存先を表示しない。保存先の切り替えは、個人データの消失・共有の重複を避けるため別の段階で設計する。

### ToDoの日付

追加時：

1. 「なんでも追加」に内容を入力
2. 「詳しく整える」を押す
3. ToDoの下の「日付」で期限日を選ぶ
4. 保存すると、選んだ日へ追加される

既存のToDo：

1. やること画面でToDoを長押し
2. 「編集」を押す
3. 「日付」を選んで保存

日付は日単位で、時刻は付けない。先の日付の上限は設けない。

## 4. データの動き

### 自分だけの予定

- 同じUUIDのまま `life-store.json` の1件を変更
- Firestoreへは送らない
- アプリを開き直しても変更後の内容を表示

### わが家で共有している予定

- 同じ `groups/{groupID}/items/{予定のUUID}` を1回更新
- 新しい文書を作らず、古い文書も削除しない
- 相手のiPhoneにもタイトル・日付・終日／時刻を反映
- `createdBy`・`createdAt`・種類・UUIDは変えない
- 更新するのは既存の決まった項目と `updatedBy`・`updatedAt` だけ

共有する種類の設定で「予定」をオフにしたあとも、すでにある共有予定は編集できる。新しい予定を共有できない決まりはBuild 14のまま。

### ToDo

- 自分だけ：同じUUIDの端末内データの日付を変更
- 共有：同じFirestore文書を1回更新し、相手側にも反映
- 日付を明示したときは「あとで」の一時的な表示先を解除し、選んだ日を正本にする
- 指定した日が今日なら「今日」、未来なら「今後」に表示
- 名前と日付を同時に変えても、共有の更新は1回だけ

## 5. 通知

- 時刻つき予定のローカル通知は、変更後の日時の10分前へ予約し直す
- UUIDを変えないため通知の識別子も同じ。古い日時と新しい日時の通知が二重にならない
- 終日に変えた場合は、その予定の時刻通知を取り消す
- 予定のプッシュ通知は追加しない

## 6. 既存機能を壊すリスクと対策

| リスク | 対策 |
| --- | --- |
| 編集で個人・共有が入れ替わる | 編集画面に保存先を出さず、元の持ち主を保持 |
| 共有予定が2件になる | 作成ではなく、同じUUIDの更新を1回だけ実行 |
| ToDo・買い物を予定編集で変える | `kind == event` の項目だけ編集可能 |
| 空のタイトルを保存する | 前後の空白を除き、空なら保存しない |
| 日付変更後も「あとで」の日が表示される | 明示して選んだ日を優先するため `deferredTo` を解除 |
| 古い通知が残る | `notificationItems` の変更で既存の一括予約し直しを実行 |
| 相手が先に予定を削除した | 存在しない予定は再作成せず、保存を失敗扱いにする |
| ToDoの日付変更で共有項目が増える | 同じUUIDを更新し、作成・削除は行わない |
| 将来日を指定できない | DatePickerに上限を付けない |
