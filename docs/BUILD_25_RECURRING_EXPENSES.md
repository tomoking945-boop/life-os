## 1. 何を作ったか

1. **定期支出の登録**：「お金」の画面の予算のカードの下・「支出を追加」の上に「定期支出」。家賃・通信費・保険・サブスクなど、毎月くり返す支出を登録する
   - 項目：名前・目安金額・カテゴリー・毎月の支払日（1〜31日）・開始月・保存先（自分だけ／わが家で共有。**初期値は自分だけ**）
   - 名前は前後の空白を除いて1〜80文字（改行・制御文字は使えない）。目安金額は 1〜999,999,999 円の整数（全角数字・カンマ・「円」「¥」は読む）。できない理由は日本語で出す
   - その日が無い月（2月の30日・31日、30日の月の31日）は、その月の最終日（うるう年の2月は29日）
2. **月ごとの候補**：表示している月に、1つの設定につき候補を1件だけ出す（開始月より前には出さない）。状態は文字で出す：**未確認・追加済み・今月は追加しない・停止中**
3. **「今月分を追加」**：ふつうの支出の確認画面を開く（名前・金額・カテゴリー・支払予定日・設定の保存先を入れておく）。**「保存」を押したときだけ**支出を1件作り、その月を「追加済み」にする
   - 日付はその月の中だけ選べる。月の外の日付は保存せず、理由を出す（「日付は2026年11月の中から選んでください」）
   - 作った支出は、ふつうの支出と同じく支出一覧・月の予算・カテゴリー別の予算・今日画面の MONEY・検索に入る
4. **「今月は追加しない」**：確認してから。支出は作らない。「未確認に戻す」で取り消せる（2台の iPhone の両方に反映）
5. **停止・再開**：停止しても、作った支出・追加済み・今月は追加しないの記録は消さない。新しい月の候補を出さなくなる。再開すると再開した月から候補を出す。Build 25 では全部を消す操作は作っていない
6. **編集**：未確認の月と、これから先の候補にだけ反映する（作った支出は変わらない）。**保存先はあとから変えない**（「停止して、新しく作ってください」と案内）
7. **今日画面の「定期支出を確認」**：今月の未確認で、支払予定日を過ぎた・今日・7日以内のものがあるときだけ、件数を1行で出す（名前・金額は出さない）。タップで「お金」の画面を開く

自動で支出を作ること・通知（プッシュ・ローカル）・通知の許可を求めること・銀行やカードとの連携・外部の AI は作っていません。

## 2. 自動で作らず「確認してから保存」にした理由

- **金額が月ごとに変わる**ことがある（電気・水道・通信費・カードの引き落とし）。自動で目安金額のまま作ると、予算・残りの金額が実際と違ってしまう
- **払わなかった月**（解約した・まとめて払った・旅行で止めた）に、払っていない支出が勝手に入ると、あとで探して消す手間が増える
- **2台で同じわが家を使う**と、自動で作る処理が2台で同時に動き、二重に作るおそれがある。押したときだけ作れば、その1回の書き込みで重複を防げる（下の「5. 重複を防ぐ」）
- 端末がしばらく閉じていても、開いたときに「未確認」として出るので、取りこぼしに気付ける

## 3. 保存先

| | 自分だけの定期支出 | わが家で共有の定期支出 |
| --- | --- | --- |
| 設定 | この iPhone の中（life-store.json の `recurringExpenses.templates`） | Firestore の `groups/{groupID}/recurringExpenses/{templateID}` |
| 月ごとの状態（追加済み・今月は追加しない） | この iPhone の中（life-store.json の `recurringExpenses.occurrences`） | Firestore の `groups/{groupID}/recurringExpenseOccurrences/{templateID}_{YYYY-MM}` |
| 作った支出 | 自分だけの支出（端末） | 共有の支出（`groups/{groupID}/expenses/{expenseID}`） |
| 送るか | **送らない**（Firestore に置き場所も無い） | わが家のメンバーだけが読み書き |
| 変えられる人 | 本人 | オーナーとパートナーのどちらも |

- 「未確認」は記録しない（記録が無い月＝未確認）
- わが家の定期支出は端末の life-store.json には保存しない（起動中だけ持ち、Firestore から読み直す）
- 以前の life-store.json（`recurringExpenses` が無い）は「定期支出なし」として読む。読めない記録・正しくない記録だけを飛ばし、ファイル全体は読める（支出・予算は失わない）
- 自分だけの定期支出で、端末に保存できなかったときは、支出と「追加済み」の両方を元に戻す（候補は未確認のまま。「保存できませんでした」と出す）

## 4. 送る情報・送らない情報（わが家で共有の定期支出だけ）

**設定（11項目だけ）**：`schemaVersion`（1）・`title`・`expectedAmount`・`category`・`dueDay`・`startMonthKey`・`isActive`・`createdBy`（作った人の UID）・`updatedBy`（変えた人の UID）・`createdAt`・`updatedAt`（サーバーの時刻）

**月ごとの状態（7項目だけ）**：`schemaVersion`（1）・`templateID`・`monthKey`（YYYY-MM）・`status`（`created`＝追加済み／`skipped`＝今月は追加しない）・`expenseID`（追加済みは作った支出の UUID、今月は追加しないは null）・`processedBy`（処理した人の UID）・`processedAt`（サーバーの時刻）

**作った共有の支出**：ふつうの共有の支出と同じ9項目（Build 13 から変えていない）

**送らないもの**：メールアドレス・表示名・端末の情報・通知のトークン・レシートの写真・読み取った全文・商品明細・検索語・自分だけの定期支出・メモ

UID・名前・金額・グループの ID・支出の ID は、画面の操作の記録（ログ）に出しません。

## 5. 重複を防ぐ仕組み

同じ設定の同じ月の支出は、**1件だけ**です（2台で同時に押しても）。

- **自分だけ**：その月の記録があれば2回目は断る（保存ボタンを続けて押す・同じ月をもう一度開く）。支出と「追加済み」は1回の保存で端末に書く
- **わが家で共有**：
  1. 月ごとの状態の文書の ID を `{templateID}_{YYYY-MM}` に決めてある（同じ月は文書1つだけ）
  2. 「今月分を追加」は、共有の支出と「追加済み」を **1回の書き込み（Firestore の WriteBatch）** で一緒に送る。全部が成功するか、全部が失敗する（片方だけにはならない）
  3. Security Rules は、「追加済み」を **新しい共有の支出と同じ書き込みのときだけ** 作らせ、**変更も削除もさせない**。同じ月の文書がすでにあれば、2台目の書き込みは全部が断られ、2台目の支出も作られない
  4. 2台目の画面では、断られた支出を消し、1台目の「追加済み」を出す（「支出は作っていません…ほかの iPhone で追加済みのときは『追加済み』になります」と出す）
- **共有の保存が断られたとき**（通信できない・権限が無い・家計簿の共有がオフ）：共有の支出を作らない、**自分だけの支出にも変えない**、候補は未確認のまま、日本語で理由を出す
  - ふつうの共有の支出（Build 13）は、断られると自分だけとして残しますが、定期支出は二重登録を防ぐため、この動きを使いません
- 作った支出を消しても「追加済み」は残り、候補は戻りません（同じ月をもう一度作らない）

## 6. 停止・再開・今月は追加しない

| 操作 | 支出 | 記録 | 候補 |
| --- | --- | --- | --- |
| 今月は追加しない | 作らない | `skipped` を置く | 「今月は追加しない」（予算に入らない） |
| 未確認に戻す | — | `skipped` を消す | 「未確認」に戻る |
| 追加済みを未確認に戻す | — | **できない**（二重に登録しないため） | 「追加済み」のまま |
| 停止 | 消さない | 消さない | 新しい月の候補を出さない（記録のある月は、その状態で出す） |
| 再開 | — | 消さない | 再開した月から出す（開始月を再開した月にする。止めていたあいだの月は出さない。開始月が先なら開始月のまま） |
| 編集 | 作った支出は変えない | 消さない | 未確認の月と先の月に反映 |

## 7. Security Rules（`firestore.rules`）

**設定** `groups/{groupID}/recurringExpenses/{templateID}`
- 読む・作る・変える：わが家のメンバーだけ（入っていない人・サインインしていない人・別のわが家の人は断る）
- 作る：家計簿（money）の共有がオンのときだけ・文書の ID は UUID・作った人は本人・作った日時はサーバーの時刻
- 変える：家計簿をオフにしたあとも変えられる。作った人・作った日時・schemaVersion は変えられない
- 11項目だけ・schemaVersion 1・名前は制御文字なしの1〜80文字・目安金額 1〜999,999,999 の整数・6つのカテゴリー・支払日 1〜31 の整数・開始月 2000-01〜2099-12・停止は真偽値・変えた人は本人・変えた日時はサーバーの時刻
- 消す：できない（Build 25 では停止だけ。わが家の削除のときはサーバーが消す）

**月ごとの状態** `groups/{groupID}/recurringExpenseOccurrences/{templateID}_{YYYY-MM}`
- 読む・作る：わが家のメンバーだけ
- 文書の ID は `templateID + "_" + monthKey`、設定（`recurringExpenses/{templateID}`）があること、7項目だけ、処理した人は本人、処理した日時はサーバーの時刻
- `created`：`expenseID` は UUID で、その共有の支出が「この書き込みの前には無く、後にある」（`!exists` と `existsAfter`）、作った人が本人
- `skipped`：`expenseID` は null
- 変える：できない。消す：`skipped` だけ（`created` は消せない）

既存のルールは緩めていません（支出・明細・予算・ToDo・招待・端末のルールは変えていない）。新しい索引は要りません（どちらも1つのコレクションをそのまま見張るだけ）。Functions・通知は変えていません。

### Mac の Rules テストで見つかったテストコードの誤り（2026-11-11）

- 失敗：`firebase/functions/test/emulator/rules.test.js:1578`（「月ごとの状態の形」のテスト）で `Provided document reference is from a different Firestore instance.`
- 原因：テストの書き方の誤り。`writeBatch(as('alice'))` と `doc(as('alice'), ...)` で `as()` を別々に呼んでいたため、1回の書き込み（batch）と文書の参照が別の Firestore のつなぎ先になっていた（Rules・アプリ本体の問題ではない）
- 修正：`const aliceDb = as('alice')` を1つ作り、`writeBatch(aliceDb)` と `doc(aliceDb, ...)` の両方で使う形にした。確かめる中身（`created` の `expenseID` が UUID でなければ断られる）は変えていない
- ほかの batch（同じファイルの11か所）も検索して確かめた：どれも1つのつなぎ先から batch と文書の参照を作っており、混ざっているのはこの1か所だけだった
- Rules・アプリ本体・ほかのテストは変えていない。テストの削除・スキップ・条件をゆるめることはしていない

## 10. Firebase の公開が必要か・公開順序

**Firestore のルールの公開が必要です**（索引・Functions・Hosting は不要）。

1. Mac でテスト（下の「11. Mac での手順」）がすべて成功
2. **Firestore のルールだけを公開**：`firebase deploy --only firestore:rules`（`firebase deploy` だけのコマンドは使わない）
3. そのあとで Build 25 を TestFlight へアップロード

ルールを公開する前に Build 25 を使うと、わが家で共有の定期支出の保存・今月分を追加はルールに断られ（支出は作らない・自分だけにも変えない・元に戻る）、自分だけの定期支出・ほかの機能は今までどおり使えます。
Build 24 以前のアプリは定期支出の場所を読み書きしないので、ルールを先に公開しても影響はありません。

元に戻す方法：アプリを Build 24 に戻すと定期支出の表示が無くなります（端末の `recurringExpenses` は読まずに残るだけ。作った支出はふつうの支出として残る）。ルールの定期支出の部分を消して公開し直すと、わが家の定期支出は読み書きできなくなります（文書は残る）。

## 12. 実機確認手順（2台の iPhone。わが家で家計簿を共有している状態で）

1. iPhone A：「お金」→「定期支出を登録」。名前「テスト家賃」・目安金額・支払日・開始月を入れ、保存先「自分だけ」で保存 → 「自分だけ」に「未確認」で出る。iPhone B には出ない
2. iPhone A：「今月分を追加」→ 確認画面で金額を少し変えて「保存」→ 支出一覧・予算のカード・今日画面の MONEY に入り、候補が「追加済み」になる
3. iPhone A：同じ候補の「今月分を追加」がもう押せないこと
4. iPhone A：保存先「わが家で共有」で別の定期支出を登録 → iPhone B に出る
5. iPhone B：その定期支出を編集（目安金額）→ iPhone A に反映
6. 2台で同時に（できるだけ同じタイミングで）「今月分を追加」→「保存」→ わが家の支出は1件だけ。両方の画面で「追加済み」。片方に「追加できませんでした…」が出てもよい
7. 次の月を表示 →「今月は追加しない」→ 確認 → 支出は増えない。もう1台にも「今月は追加しない」→「未確認に戻す」で両方とも未確認に戻る
8. 「停止」→ 次の月に候補が出ない。前の月の支出・「追加済み」は残る →「再開」→ 今月から候補が出る
9. 支払日が今日〜7日以内の未確認があるとき、今日画面に「定期支出を確認」→ タップで「お金」の画面が開く（支出は自動で作られない）
10. 機内モードで、わが家で共有の定期支出の「今月分を追加」→ 保存 → 通信が戻ったあと1件だけ。断られた場合は支出が無く未確認のまま
11. 作った支出を消す → 候補は「追加済み」のまま（もう一度は作れない）
12. VoiceOver で、定期支出の行が「名前・状態・目安金額・支払日・カテゴリー・保存先」の順に読まれる。ボタンが押しやすい（44pt）。入力中にスクロール・背景のタップ・「完了」でキーボードが閉じる

## 13. 既知の制限

- 支出は自動で作らない（毎月、利用者が「今月分を追加」を押す）。通知も出さない
- 定期支出を全部消す操作は無い（停止だけ）。わが家の削除では消える
- 保存先（自分だけ／わが家で共有）はあとから変えられない（停止して新しく作る）
- 毎月だけ（毎週・隔月・年1回は無い）。支払日は1つだけ
- 「追加済み」は未確認に戻せない。間違えて作った支出は、支出を消す（候補は戻らない）
- 2台で同時に押したとき、2台目にはお知らせが出る（支出は1件だけで、2台目の画面も「追加済み」になる）
- 共有の「今月分を追加」は、通信が戻るまで結果が分からない（そのあいだは「追加済み」に見え、断られたら未確認に戻る）
- 今日画面の「定期支出を確認」は件数だけ（名前・金額は出さない）。今月の分だけ
