## 1. 何を作るか

「リスト」画面に Premium 専用の「大切な書類」を追加し、第1段階として保証書を管理できるようにする。

利用者は保証書・レシート・製品ラベルを写真で原本保存し、端末内の文字認識から製品名、購入日、保証期間、型番などの候補を受け取る。候補は必ず確認・修正してから保存する。紙の原本を置いた場所も一緒に記録し、保証終了前に通知する。

契約書管理は同じ「大切な書類」内の第2段階とし、このMVPでは実装しない。

## 2. なぜ必要か

- 故障時に保証書、購入日、保管場所を探す負担を減らす。
- 保証期限を忘れることによる不利益を防ぐ。
- 写真を探すアプリではなく「次に必要な行動が分かる」くらしOSの価値につながる。
- 継続して保存する理由があり、Premiumの継続価値を説明しやすい。

## 3. 画面構成

5タブは変更しない。「リスト」画面の通常リストより上に、小さな専用セクションを追加する。

```text
リスト

大切な書類                         Premium
┌─────────────────────┐
│ 保証書                         3件 › │
│ 次の期限：冷蔵庫　あと28日          │
└─────────────────────┘

いつものリスト
・行きたい場所
・観たいもの
```

### Freeの場合

- 「大切な書類」の入口と説明は表示する。
- 押すと「保証書を、探さなくていい場所へ」という説明とPremium案内を表示する。
- 実在する利用者データの見本は表示しない。

### Premiumの場合

- 保証書一覧を開く。
- 右上の「＋」から登録する。
- 一覧は「期限が近い」「保証期間中」「期限終了」の順で確認できる。
- 検索対象は製品名、メーカー、型番、購入店、保管場所。

### Premium終了後

- 保存済み保証書の閲覧、写真表示、書き出し、削除は可能。
- 新規登録、編集、自動読み取り、新しい期限通知の予約は停止する。
- 再加入すると同じデータから再開できる。
- 解約時にデータを削除しない。

## 4. 登録フロー

```text
保証書一覧
  ↓ ＋
写真を追加
  ├ カメラで撮る
  ├ 写真から選ぶ
  └ あとで追加
  ↓
端末内で文字を読み取る
  ↓
読み取り結果の確認
  ↓
期限・保管場所・共有範囲を入力
  ↓
保存
  ↓
通知予約を更新
```

### 写真追加

- 1件につき最大10枚。
- 対応形式はHEIC、JPEG、PNG。PDFは第2段階。
- 1ファイル25MBを超える場合は追加前に案内する。
- 画像をJPEGへ再圧縮せず、選択・撮影時のデータをそのままアプリ専用領域へ保存する。
- 同じ画像の二重登録はSHA-256で検出し、確認を出す。
- 撮影・選択をキャンセルしても空の保証書を作らない。

### 自動読み取り

- Apple Visionの `VNRecognizeTextRequest` を端末内で使用する。
- 外部AIへ画像や認識文字を送らない。
- 候補項目：製品名、メーカー、購入店、購入日、保証期間、保証終了日、型番、製造番号。
- 複数候補や信頼度が低い項目は「確認が必要」と表示する。
- 既に利用者が入力した値を自動で上書きしない。
- 「候補を反映」を押すまでは正式データに保存しない。
- AIや文字認識だけで保証の有効性を断定しない。

## 5. 入力項目

| 項目 | 必須 | 初期値・補足 |
|---|---:|---|
| 製品名 | 必須 | 自動読み取り候補。空なら保存不可 |
| カテゴリー | 任意 | 家電／家具／デジタル／住宅設備／その他 |
| メーカー | 任意 | 自動読み取り候補 |
| 型番 | 任意 | 自動読み取り候補 |
| 製造番号 | 任意 | 自動読み取り候補。通知本文には出さない |
| 購入店 | 任意 | 自動読み取り候補 |
| 購入日 | 任意 | 自動読み取り候補 |
| 保証期間 | 任意 | 日／月／年。例：1年 |
| 保証終了日 | 任意 | 購入日＋保証期間から計算。直接修正可 |
| 保管場所 | 任意 | 例：リビングの書類ケース、上から2段目 |
| メモ | 任意 | 修理窓口など |
| 写真 | 任意 | 0〜10枚。後から追加可能 |
| 所有範囲 | 必須 | 初期値は「自分」。共有は明示的に選ぶ |
| 通知 | 任意 | 初期値は30日前・7日前・当日 |

保証終了日を計算した場合は、算出根拠を「購入日 2026/10/13 ＋ 1年」のように表示する。購入日の応当日が存在しない場合は、その月の末日とする。

## 6. データモデル

```swift
struct WarrantyDocument: Identifiable, Hashable, Codable {
    let id: UUID
    var title: String
    var category: WarrantyCategory
    var manufacturer: String?
    var modelNumber: String?
    var serialNumber: String?
    var retailer: String?
    var purchaseDate: Date?
    var warrantyDuration: WarrantyDuration?
    var warrantyExpiresAt: Date?
    var expirationSource: WarrantyExpirationSource
    var physicalStorageLocation: String?
    var note: String?
    var ownership: Ownership
    var attachmentIDs: [UUID]
    var reminderOffsetsInDays: Set<Int>
    var createdAt: Date
    var updatedAt: Date
}

struct WarrantyAttachment: Identifiable, Hashable, Codable {
    let id: UUID
    let documentID: UUID
    var originalFileName: String
    var uniformTypeIdentifier: String
    var byteCount: Int64
    var sha256: String
    var relativeFilePath: String
    var createdAt: Date
}

struct WarrantyExtractionProposal: Hashable {
    var recognizedText: String
    var fields: [WarrantyExtractedField]
}
```

`WarrantyExtractionProposal` は確認中だけ保持し、利用者が反映しなかった候補は保存しない。検索用の全文保存はMVPでは行わない。

## 7. 保存場所と安全性

- メタデータ：既存の端末内JSON保存へ後方互換で追加する。
- 写真：`Application Support/LifeOS/WarrantyDocuments/{documentID}/` に保存する。
- ファイル名は利用者の製品名を使わず、UUIDにする。
- iOS Data Protectionを `.complete` に設定し、端末ロック中は読み出せないようにする。
- 一時ファイルは読み取り完了またはキャンセル時に削除する。
- 削除時はメタデータと添付ファイルを両方削除する。
- アプリ削除時は端末内データも消えることを初回登録時に説明する。
- MVPではクラウド同期・外部AI送信を行わない。

写真のGPS等のメタデータは原本保存では保持される。将来、共有・外部送信・書き出しを追加するときは、位置情報を削除したコピーを作るか利用者へ選択を出す。

## 8. 通知仕様

- 初期値：保証終了30日前、7日前、当日9:00。
- 通知文例：「冷蔵庫の保証終了まであと30日です」
- 製造番号、保管場所、写真内容は通知本文に表示しない。
- 終了日が無い場合は通知しない。
- 終了済み、削除済み、通知OFFの保証書は予約しない。
- 期限やタイトルを編集したら古い予約を削除して作り直す。
- Premium終了時は保証書の通知予約だけを削除する。

iOSの保留通知数には上限があるため、既存の予定・タスク通知と保証書通知を別々に上限まで登録しない。`LifeNotificationService` を統合スケジューラーに変更し、アプリ管理分を合計60件以内にする。

MVPの予約枠：

- 保証書：期限が近い6件 × 最大3通知 = 18件
- 時刻つき予定：直近40件
- 未完了タスク：最大1件
- 合計：最大59件

アプリ起動、保証書の追加・編集・削除、通知設定変更時に全体を再同期する。

## 9. 「今日」画面への表示

- 保証終了まで30日以内の保証書がある場合だけ、小さな「大切な書類」セクションを表示する。
- 最も期限が近い1件を表示し、「すべて見る」で保証書一覧へ進む。
- 不安を煽る赤色ではなく、既存のWarm Gold系を使用する。
- 文言例：「冷蔵庫の保証があと28日です」「購入店と保証書を確認」
- FreeまたはPremium終了後は、保存済みデータがある場合だけ閲覧入口として表示する。

## 11. 既存機能を壊すリスクと対策

| リスク | 対策 |
|---|---|
| 古い保存データが読めない | Snapshotの保証書をOptionalにし、無い場合は空配列 |
| 写真で容量を圧迫 | 枚数・ファイルサイズ制限、使用容量表示、個別削除 |
| 読み取り間違い | Preview承認制。既存入力を上書きしない |
| 個人資料を誤共有 | 初期値は自分。共有前に写真枚数と項目名を再確認 |
| 通知上限超過 | 既存通知と統合し合計59件まで |
| Premium終了時に閲覧不能 | 閲覧・書き出し・削除は常に許可 |
| 写真だけ残る | 削除と保存失敗時のロールバック、孤立ファイル清掃テスト |

## 12. テスト方法

### Unit Test

- 購入日＋1年、うるう日、月末の保証終了日計算。
- 以前のSnapshotから保証書が空で読み込める。
- 追加・編集・削除後に再起動しても残る。
- Freeは新規登録不可、Premiumは可能。
- Premium終了後も閲覧・書き出し・削除が可能。
- 自分／共有の初期値と変更。
- 通知日が過去の場合は予約しない。
- 既存通知を含め合計59件以下。
- 削除した保証書の通知と画像が残らない。

### UI・実機確認

- カメラ権限拒否、写真権限拒否、限定アクセスでも壊れない。
- HEIC、JPEG、PNGを原本のまま再表示できる。
- 日本語の保証書、レシート、製品ラベルを読み取れる。
- 読み取り失敗後も手入力で保存できる。
- VoiceOver、文字サイズ最大、ダークモードで操作できる。
- 端末ロック中に保護ファイルを読めない。
- 実通知が30日前・7日前・当日の設定どおりになる。

## 13. 成功条件

- 保証書を撮影して1分以内に保存できる。
- 製品名だけ入力すれば、読み取り失敗時でも保存できる。
- 保証終了日と紙の保管場所を一覧・詳細から確認できる。
- AI候補は承認前にデータへ反映されない。
- 写真と認識文字が外部サービスへ送信されない。
- 既存の予定・タスク通知と合わせて通知予約が上限を超えない。
- 既存XCTestと新規テストがすべて成功する。

## 14. 第2段階：契約書管理（今回の対象外）

保証書MVPの安全性と利用状況を確認後、契約名、契約相手、開始日、終了日、自動更新、解約期限、金額、原本保管場所、写真・PDFを追加する。

契約書は機密性が高いため、初期値は必ず「自分」。法的判断や契約の有効性判定は行わず、端末内の文字認識候補と期限管理に限定する。
