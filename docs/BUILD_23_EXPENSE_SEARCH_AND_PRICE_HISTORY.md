## 何を作ったか

1. **家計簿の検索**：「お金」の画面の上に検索欄。店名・支出のタイトルと、商品明細の商品名から、部分一致で支出を探す
2. **絞り込み**：すべて／自分／共有（画面上部の今までの切り替えと同じ）・月・カテゴリー
3. **商品の購入履歴**：支出の詳細で商品明細をタップすると開く。購入回数・最新の購入日・購入ごとの日付・店名・商品の金額・数量・単価・自分だけ／共有（新しい順）
4. **過去の参考価格**：比べられる購入記録だけで、最新の参考価格・これまでの最安・最高・前回との差（店名と購入日つき）

インターネットでの価格の検索・価格の予測・買い物のおすすめ・外部の AI・グラフは作っていません。

## 検索

### 検索の対象

- 支出のタイトル（レシートから保存したときは店名）
- 商品明細の商品名（Build 21 から保存している明細）

### 検索の仕方（`ExpenseSearchText.normalized`）

検索語と、店名・商品名の両方を同じ形に整えてから比べます。

| 整え方 | 例 |
| --- | --- |
| 前後の空白を除く | 「 牛乳 」→「牛乳」 |
| 全角・半角をそろえる（Unicode の互換の正規化 NFKC） | 「ＦＩＣＴＩＯＮ」→「fiction」、「５００ｍｌ」→「500ml」、「ｷﾞｭｳﾆｭｳ」→「ギュウニュウ」、全角の空白 → 半角の空白 |
| 英字の大文字・小文字を区別しない | 「Green Tea」と「green tea」 |
| 続く空白（タブ・改行も）を1つにする | 「まちの　　八百屋」→「まちの 八百屋」 |
| 日本語は壊さない | ひらがな・カタカナ・漢字はそのまま（ひらがなとカタカナは別の文字として扱う） |

- 部分一致です（「百屋」で「まちの八百屋」、「脂肪」で「低脂肪牛乳」）
- 検索語は1つのまとまりとして探します（「まちの 八百屋」は、その並びのまま）
- 検索語が空（空白だけも）なら、検索をやめて通常の一覧に戻ります。検索欄の「×」（検索語を消す）を押すと、月・カテゴリーの絞り込みも戻します

### 検索結果に出すもの

- 店名・支出のタイトル、日付（今年なら「11/5（木）」、ほかの年は年つき）、支出の合計（右寄せ）、カテゴリー、自分だけ／わが家で共有（文字で。共有は印も）
- 商品名で一致したときは、一致した商品名と金額（3件まで。それより多ければ「ほか n件の商品が一致」）
- 同じ支出の複数の商品が一致しても、支出は1件だけ
- 新しい日付の順
- 検索中は件数（「検索結果 n件」）。0件なら「該当する支出はありません」
- 結果をタップすると、今までの支出の詳細を開く（そこから明細の購入履歴へ）

### 絞り込み

- **すべて／自分／共有**：画面上部の今までの切り替えをそのまま使う（一人で使う設定では切り替えを出さず、すべて）
- **月**：支出のある月だけを、新しい順にメニューで出す（「すべての月」に戻せる）
- **カテゴリー**：食費・日用品・外食・交通・サブスク・その他（「すべてのカテゴリー」に戻せる）
- 組み合わせて使える（例：共有・2026年10月・日用品）

## 商品の購入履歴

支出の詳細で商品明細をタップすると、「購入履歴」を同じ画面の中で開きます（戻ると詳細）。
Build 21 では明細のタップで「直す」欄が開きましたが、Build 23 からは **鉛筆のボタン** で直します（ごみ箱で消すのは今までどおり）。

### 同じ商品としてまとめる条件

- 商品名の **前後の空白・全角半角・英字の大小・続く空白だけ** を整え、**整えた名前が同じものだけ** を同じ商品にします
- あいまいな一致・推測・AI で、別の商品をまとめません。「牛乳」と「低脂肪牛乳」「牛乳 1000ml」は別の商品です
- 利用者が商品名を直すと、そのあとの履歴のまとまりも新しい名前で作ります（履歴は開くたびに今の明細から作る）
- 表示している範囲（すべて／自分／共有）の支出だけを使い、購入記録ごとに「自分だけ」「わが家で共有」を文字で出します

### 表示するもの

- 商品名・購入回数・最新の購入日・対象の範囲
- 購入ごとの記録（新しい順）：日付・店名・自分だけ／共有・商品の金額（右寄せ）・数量・単価（または参考単価）

## 過去の参考価格

比べられる購入記録があるときだけ、小さな要約を出します（グラフは作らない）。

| 項目 | 内容 |
| --- | --- |
| 最新の参考価格 | いちばん新しい、比べられる購入記録の単価（店名・購入日つき） |
| これまでの最安（参考） | 比べられる購入記録が2件以上のときだけ。同じ価格なら新しい方 |
| これまでの最高（参考） | 同上 |
| 前回との差 | 最新と、そのひとつ前の比べられる購入記録の差（「前回より ¥20 高い」「前回より ¥30 安い」「前回と同じ」） |

### 価格を比べる条件（`PurchaseHistory.price`）

1. **単価が保存されていれば、単価を使う**（金額÷数量より優先）
2. 単価が無く、**数量が正しい（0 より大きく 10000 未満・小数3桁まで）とき** だけ、「金額 ÷ 数量」で **参考単価** を計算する（1円未満は四捨五入）
3. それ以外は比べない

### 比べない場合

| 場合 | 扱い |
| --- | --- |
| 数量も単価も分からない | 商品の金額だけを出し、「単価は比較できません」 |
| 数量が 0・負の数・範囲の外 | 比べない（0 で割らない） |
| 金額・単価が 0円・負の数・999,999,999 円を超える | 比べない（正しくない単価は使わず、正しい数量と金額があれば参考単価） |
| 比べられる記録が1件だけ | 最新の参考価格だけ（最安・最高・前回との差は出さない） |
| 比べられる記録と、比べられない記録が混ざる | 比べられる記録だけで要約し、「単価が分からない購入記録 n件は、比べていません」 |

- 外れ値の推測（「ほかと比べて高すぎるので除く」など）はしていません。正しくない値だけを除きます
- 内容量や単位（「1000ml」「100g」など）は保存していないため、**どちらがお得かは決めません**。文言は「過去の購入記録」「参考価格」で、購入をすすめる文はありません

## 自分だけ／共有の扱い

- Build 21 の決まりのまま：自分だけの支出と明細は端末の中（life-store.json）だけ、共有の支出と明細は今までの Firestore の場所（`groups/{groupID}/expenses`・`expenseLineItems`）だけ
- 検索・購入履歴は、すでに端末に読み込んである支出と明細を **読むだけ**（Firestore へ新しい問い合わせを送らない・新しい見張りを作らない）
- 自分だけ⇔共有を変えている途中（両方にある途中）も、今までどおり1件だけ（自分だけの方）を使うので、検索結果・購入履歴に重ねて出しません
- 明細をまとめて読む部品（`lineItemsByExpense`）は、1件ずつ読むときと同じ決まり（自分だけの支出は端末の明細、共有の支出はわが家の明細）

## 保存・送信しない情報

新しい保存先・データの形は作っていません（支出・明細の形は Build 21 と同じ）。次のものは、保存も送信もしません（画面のあいだのメモリの中だけ）。

- 検索語・絞り込み（月・カテゴリー）
- 見た商品（購入履歴を開いた商品）
- 価格を比べた結果（最安・最高・前回との差）
- 商品名・金額を含むログ（新しく足したファイル・変えた画面に `print`・`Logger` などは無い）
- レシートの写真・読み取った全文（Build 22 までと同じ）
- 外部サービスへの家計の情報

## 性能の対策

- 検索・購入履歴は端末の中の計算だけ。文字を入れるたびに Firestore へ問い合わせない・見張りを増やさない
- 明細はまとめて1回で読む（`LifeStore.lineItemsByExpense`。支出ごとに一覧を調べ直さない）
- 検索は支出1件・明細1件をそれぞれ1回ずつだけ調べる（テストで「調べた数」を確かめる）
- 同じ支出は1回だけ（重ねない・複製しない）
- 画面を開いたり閉じたりしても、見張りの数は変わらない（テストで数を確かめる）
- 支出・明細を直す・消す・自分だけ⇔共有を変えると、検索結果・購入履歴はすぐに新しくなる（保存した結果を持たず、毎回今のデータから作るため）
- 支出1,000件・明細5,000件で、調べた数・結果の数・重なりが無いことをテストで確かめる（時間だけに頼らない）

## 実機確認手順（Build 23）

検索：

1. お金 → 上の検索欄に店名の一部を入れる → その支出が出る・「検索結果 n件」
2. 商品名の一部（例：牛乳）を入れる → その商品がある支出が1件ずつ出て、「一致した商品：牛乳 ¥198」
3. 英字の大小・全角半角を変えて入れても同じ結果
4. すべて／自分／共有を切り替える → 自分だけ・共有の支出が混ざらない（行に「自分だけ」「わが家で共有」と出る）
5. 月・カテゴリーのメニューで絞り込む（組み合わせも）
6. 見つからない言葉 →「該当する支出はありません」
7. 「×」を押す → 通常の一覧に戻る
8. 検索中に、背景のタップ・スクロール・「完了」でキーボードが閉じる
9. 結果をタップ → 今までの支出の詳細が開く

購入履歴：

1. 支出の詳細で商品明細をタップ → 「購入履歴」が開く（購入回数・最新の購入日・新しい順の記録）
2. 単価のある商品 → 最新の参考価格・最安・最高・前回との差（店名・日付つき）
3. 数量・単価の無い商品 → 金額だけ・「単価は比較できません」
4. 「牛乳」と「低脂肪牛乳」が別の商品として出る
5. 詳細の鉛筆のボタンで商品名を直す → 購入履歴のまとまりが変わる
6. 明細・支出を消す・自分だけ⇔共有を変える → 検索結果・購入履歴が新しくなり、重ならない
7. VoiceOver で、検索欄・消すボタン・結果の行・購入記録が読み上げられる

今までの機能：レシートの読み取り・数字の候補・明細の保存と修正と削除・保証書の読み取り・予定・ToDo・買い物・通知・招待・以前の支出・キーボードを閉じる動き。
支出の多い状態で、検索の入力が重くならないかも見てください。

## 既知の制限

- ひらがなとカタカナ（「ぎゅうにゅう」と「ギュウニュウ」）、漢字とかな（「牛乳」と「ぎゅうにゅう」）は別の文字として探します（推測でまとめない）
- 「ー」と「-」など、形の似た別の記号は同じにしません
- 検索語は1つのまとまり（「牛乳 パン」で、牛乳とパンの両方がある支出を探す、のような探し方はしない）
- 内容量・単位を保存していないため、「どちらがお得か」は分かりません。数量が分からない購入記録は、単価を比べません
- 外れ値の推測はしない（正しくない値だけを除く）
- 購入履歴から、その支出の詳細へは移れません（詳細から履歴へだけ）
- 検索は端末に読み込んである支出と明細だけ（共有の支出は、わが家の見張りが読み込んだ分。インターネットの価格は調べない）
- グラフ・価格の予測・買い物のおすすめは作っていません

## リスク

- **明細のタップの意味が変わった**：Build 21・22 では明細のタップで直す欄が開いたが、Build 23 からは購入履歴。直すのは鉛筆のボタン。実機で迷わないか確かめる
- **支出がとても多いとき**：検索は入力のたびに端末の中で全件を調べ直す（支出1,000件・明細5,000件はテストで確かめたが、時間は実機で見る）
- **全角半角のそろえ方**：Unicode の互換の正規化（NFKC）を使うため、「①」が「1」、「㈱」が「(株)」になるなど、検索では同じ文字として扱われるものがある（保存している名前は変えない）
- **キーボードを閉じる仕組みが、お金の画面にも付いた**：Build 22 と同じ「タップを奪わない」仕組みなので、ボタンの動きは変わらない見込みだが、お金の画面で入力中に別の場所をタップするとキーボードが閉じる（実機で確かめる）
- **Xcode で未実行**：画面（SwiftUI）の組み立てとテストは Mac で確かめる
